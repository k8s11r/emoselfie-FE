# FE-2 · onboarding

**의존** FE-1 shell
**요구사항** RO-01, RO-03, RO-05, RO-15, RO-17, RD-01, RD-04, ID-04, PM-16
**화면** 1 랜딩 · 2 닉네임 설정 · 11 오류
**결정** C-8 (링크 전용), C-9 (방 이름 없음), C-5 (제한시간)

---

## 목표

링크를 받은 사람이 3분 안에 게임에 도달하게 한다. 여기서 막히면 PRD의 G1이 무너진다.

---

## 화면 1 — 랜딩

담는 것:

- **방 만들기** — 라운드 수 · 제한시간 설정 포함 (RO-17)
- **카메라 필수 안내** (PM-16)
- 게임 설명

**두지 않는 것:**

```
❌ 코드 입력란            링크 전용이다 (RO-05, C-8)
❌ 방 이름 입력·랜덤 버튼  방에는 이름이 없다 (C-9)
```

### 설정 UI

```
라운드 수    [ 3 ]  [ 5 ]  [ 7 ]         기본 5      RD-01
제한시간     [ 15초 ] [ 20초 ] [ 30초 ]  기본 20초   RD-03, RD-04
```

**같은 칩 UI 패턴을 두 곳에 재사용한다** (C-5). 제한시간은 v1.0에서 P1 → P0로 승격됐다.

허용값 밖의 값을 만들 수 있는 입력(자유 숫자 입력 등)을 두지 않는다.

### 카메라 필수 고지 (PM-16)

랜딩과 사전 안내 화면 양쪽에 **"카메라가 필요한 게임"** 임을 명시한다. 뒤늦게 참여 불가를 알게 되는 상황을 줄이기 위한 요구사항이다.

여기서는 **권한을 요청하지 않는다.** 고지만 한다 (PM-01).

### 방 만들기 흐름

```
POST /api/rooms {roundCount, timeLimitSec, emotionSet}
  → 201 {slug}                      → /r/{slug}/nickname
  → 200 {redirected: true, slug}    → /r/{slug}/lobby
                                      + 토스트 "이미 만든 방으로 이동했어요"
```

`redirected`는 **에러가 아니다** (RO-03). 에러 UI를 띄우지 않는다. 새 방을 만들려면 대기실에서 기존 방을 닫아야 한다는 안내를 토스트에 함께 담는다.

## 화면 2 — 닉네임 설정

| ID | 규칙 |
|---|---|
| RO-05 | 닉네임 **2~10자**. |
| ID-04 | **재접속 시 기존 값을 입력란에 자동으로 채운다.** 매번 변경 가능. |
| — | 프로필 색상 자동 배정. 사용자가 고르지 않는다. |

`GET /api/session`으로 저장된 닉네임을 받아 기본값으로 넣는다. 로컬 저장소에 캐시하지 않는다 — 서버가 UUID에 붙여 기억한다.

검증은 서버가 최종 판정하지만, 입력 중 즉시 피드백을 준다.

```
2자 미만  → "2자 이상 입력해 주세요"
10자 초과 → 입력 차단
공백만     → 제출 비활성
```

같은 방 내 닉네임 중복은 **MVP에서 허용**한다 (PRD 13장 미결 2번). 색상 태그로 구분된다.

닉네임 확정 후 → `/r/{slug}/camera` (화면 3, FE-3).

## 화면 11 — 오류

| 상황 | 문구 | 액션 | 근거 |
|---|---|---|---|
| 없거나 종료된 링크 | "방을 찾을 수 없어요" | 방 만들기 제안 | RO-15 |
| 정원 초과 | "방이 가득 찼어요" | 새로고침 재시도 | RO-06 |
| 서버 점검 | 안내 문구 | — | — |

`GET /api/rooms/{slug}`가 입장 전 호출이므로, **응답에 참여자 목록이나 설정 상세가 없어도 정상이다.** 없는 정보를 채워 넣으려 하지 않는다.

## 링크 공유

```
emoselfie.app/r/Xk9mQ2vB7nLp
```

12자 URL-safe slug (RO-01, C-8). FE는 slug를 생성하거나 검증하지 않는다. 서버가 준 URL을 그대로 쓴다.

`CODE` 배지를 그리지 않는다 (C-8에서 삭제).

## 테스트

- 랜딩에 코드 입력란이 없다
- 랜딩에 방 이름 입력이 없다
- 라운드 수 3/5/7, 제한시간 15/20/30 외의 값을 만들 수 없다
- 기본값이 5라운드 / 20초다
- `redirected: true` → 에러 UI 없이 대기실 + 토스트
- 닉네임 1자 거부, 10자 허용, 11자 입력 차단, 공백만 거부
- 재접속 시 기존 닉네임이 입력란에 채워진다 (ID-04)
- 닉네임을 localStorage에 쓰지 않는다
- 종료된 slug → "방을 찾을 수 없어요" + 방 만들기 제안
- 정원 초과 → "방이 가득 찼어요"
- 랜딩·사전 안내 양쪽에 카메라 필수 문구가 있다 (PM-16)
- **랜딩에서 `getUserMedia`가 호출되지 않는다** (PM-01)

## 하지 않는 것

```
❌ 코드 입력란 (C-8)
❌ 방 이름 입력·랜덤 생성 (C-9)
❌ 랜딩·닉네임 단계에서 권한 요청 (PM-01)
❌ redirected 를 에러로 표시 (RO-03)
❌ 닉네임을 로컬 저장소에 캐시
❌ slug를 FE에서 생성·검증
❌ CODE 배지 렌더링
❌ 허용값 밖의 설정을 만들 수 있는 입력
```
