# FE-8 · resilience

**의존** 횡단 — FE-1, FE-3, FE-5, FE-6에 훅을 건다
**요구사항** ID-05, PM-12, PM-13, 7.2, 7.3 · 가이드 §9
**화면** 없음 (동작 계층)

---

## 목표

**모바일 네트워크는 안정적이지 않다는 것을 기본 전제로 한다.**

다음을 예외가 아니라 **정상적인 사용자 행동**으로 취급한다.

```
Wi-Fi → LTE       LTE → Wi-Fi
브라우저 background   일시적 연결 끊김
페이지 reload      전화 수신   화면 잠금
```

목표는 7.2의 한 줄이다: **일시적 연결 끊김 시 10초 이내 재접속하면 진행 중인 라운드에 복귀할 수 있어야 한다.**

---

## 소켓 재연결

Socket.IO의 자동 재연결을 켜되, **재연결만으로 상태가 완전히 복구된다고 가정하지 않는다** (가이드 §9).

끊긴 동안 놓친 이벤트는 다시 오지 않는다. `submission:scored` 3건을 놓치면 레일이 비어 있는 채로 남는다.

```
socket disconnect
      ↓
연결 상태 UI 표시 (무한 스피너 아님 — 시도 횟수·상태를 보여준다)
      ↓
socket reconnect
      ↓
GET /api/rooms/{slug}/snapshot     ← 반드시 스냅샷을 다시 받는다
      ↓
스토어 전체 교체
      ↓
서버 상태에 맞는 화면으로 라우팅
```

**재연결 후 스냅샷 재요청이 이 모듈의 핵심이다.** 이게 없으면 소켓만 붙고 화면은 과거에 머문다.

재연결 시도 중에도 화면을 지우지 않는다. 마지막 상태를 흐리게 유지하고 상단에 연결 배너를 띄운다. **[가정]**

## 스냅샷 복원

| ID | 규칙 |
|---|---|
| ID-05 | 새로고침·재접속 시 쿠키 UUID로 기존 참여자 세션에 복귀한다. 게임 진행 중이면 **현재 라운드 상태와 누적 포인트를 복원**한다. |

복원 대상 (가이드 §9):

```
현재 방              참여자 목록
방장 여부            현재 게임 상태
현재 라운드          라운드 마감 시각
자신의 제출 상태      누적 포인트
```

추가로 필요한 것:

```
현재 라운드의 결과 (제출자인 경우)
미제출 여부 (RS-11 대상인지)
리액션·스킵 현황
```

### 복원 후 라우팅

서버 상태가 화면을 결정한다.

| 서버 상태 | 화면 |
|---|---|
| `waiting` | 5 대기실 |
| `countdown` | 6 라운드 시작 |
| `capturing` + 내 제출 없음 | 7 촬영 |
| `capturing` + 내 제출 있음 | 8 라운드 결과 |
| `scoring` / `finalized` + 제출함 | 8 라운드 결과 |
| `scoring` / `finalized` + `missed` | 9 미참여 안내 |
| `finished` | 10 최종 결과 |

사용자가 URL을 직접 쳐도 서버 상태가 이긴다 (FE-1).

**스냅샷에 결과가 없으면 그것이 정상이다.** 미제출자에게 서버가 결과를 주지 않기 때문이다 (RS-12). 에러로 처리하거나 재요청하지 않는다.

### 복원할 수 없는 것

**촬영한 이미지는 복원되지 않는다.** 새로고침하면 Blob이 사라진다. 브라우저 저장소에 넣지 않기 때문이다 (가이드 §5.3) — 이것은 의도된 동작이다.

제출 전에 새로고침한 사용자는 다시 찍어야 한다. 남은 시간이 있으면 촬영 화면으로 보내고, 없으면 미제출 처리된다.

## 카메라 복원

| ID | 규칙 |
|---|---|
| PM-12 | 새로고침·재접속 시 이전 권한 상태를 재확인하고, **이미 허용된 경우 추가 요청 없이 준비 완료로 복원**한다. |
| PM-13 | 앱 전환·화면 잠금으로 스트림이 중단된 뒤 복귀하면 **프리뷰를 자동 재개**한다. 실패 시 "카메라 다시 켜기" 버튼을 노출한다. |

```ts
useVisibilityResume()   // visibilitychange, pagehide/pageshow
```

복귀 시 순서:

```
1. 소켓 상태 확인 → 끊겼으면 재연결 + 스냅샷
2. 카메라 트랙 readyState 확인 → 'ended' 면 스트림 재생성
3. 서버 시각 오프셋 재동기화
4. 서버 상태에 맞는 화면으로 라우팅
```

3번을 빠뜨리기 쉽다. 백그라운드에 오래 있던 탭은 타이머가 멈춰 있었으므로 복귀 시 남은 시간이 틀어진다.

권한 재확인은 `getUserMedia`를 다시 호출하는 것이 아니다. 이미 허용된 상태면 다이얼로그가 뜨지 않지만, Permissions API로 먼저 확인해 불필요한 호출을 줄인다 (PM-15 대응 포함).

구현은 FE-3의 `useCameraStream`이 담당하고, 이 모듈은 **언제 그것을 부를지**를 정한다.

## 촬영 중 이탈

PRD 10장:

| 상황 | 처리 |
|---|---|
| 촬영 중 전화 수신·앱 전환 | 복귀 시 프리뷰 자동 재개. **제한시간은 계속 흐르며 별도 보정하지 않는다** |
| 라운드 도중 이탈 | 해당 라운드 미제출 처리. 재접속 시 다음 라운드부터 복귀 |

시간을 보정해 달라고 서버에 요청하지 않는다. 마감은 절대 시각으로 이미 정해져 있다 (RD-08).

## 연결 상태 UI

**무한 로딩 상태를 만들지 않는다** (PRD 6.5, 가이드 §11).

| 상태 | 표시 |
|---|---|
| 재연결 시도 중 | "연결 중… (2회 시도)" 배너 |
| 재연결 성공 | 배너 사라짐. 화면 갱신 |
| 장기 실패 | 새로고침 안내 + 버튼 |

모든 대기 화면에 남은 시간·진행 상황·남은 인원 중 하나가 보여야 한다.

## 테스트

### 자동

- 소켓 disconnect → 재연결 → **스냅샷 재요청이 발생한다**
- 스냅샷 수신 → 스토어 전체 교체
- 서버 상태별 라우팅 (위 표 7가지 전부)
- `missed` 상태 → 화면 9, 결과 없음을 에러로 처리하지 않는다
- 재연결 중 화면이 비워지지 않는다
- 재연결 배너에 시도 횟수가 보인다
- 복귀 시 서버 시각 오프셋이 재동기화된다
- `visibilitychange` → 트랙 `ended` → 스트림 재생성
- 새로고침 후 촬영 Blob이 없는 것이 정상 처리된다
- 장기 실패 시 새로고침 안내

### 실기기 (필수)

```
□ Wi-Fi → LTE 전환 → 소켓 재연결 + 상태 복원
□ LTE → Wi-Fi 전환 → 동일
□ 촬영 중 전화 수신 → 복귀 → 프리뷰 재개, 타이머 정확
□ 결과 화면에서 앱 전환 → 복귀 → 레일·리액션 현황 정확
□ 페이지 새로고침 (대기실 / 촬영 / 결과 / 최종) → 각각 올바른 화면 복귀
□ 백그라운드 60초 후 복귀 → 남은 시간이 정확 (오프셋 재동기화)
□ 10초 이내 재접속 → 진행 중인 라운드 복귀 (7.2)
□ 기내 모드 10초 → 해제 → 복귀
□ 화면 잠금 → 해제 → 프리뷰 재개
```

## 하지 않는 것

```
❌ socket 재연결만으로 상태 복구를 가정 (가이드 §9)
❌ 재연결 후 스냅샷 재요청 생략
❌ 재연결 중 화면 비우기
❌ 무한 로딩 배너
❌ 복귀 시 서버 시각 오프셋 재동기화 누락
❌ 촬영 이미지를 브라우저 저장소에 넣어 복원 (§5.3)
❌ 백그라운드 시간만큼 제한시간 보정 요청 (PRD 10장)
❌ 결과 미수신을 에러로 처리 (RS-12)
❌ 복귀 시 getUserMedia 무조건 재호출
❌ FE가 복원 후 화면을 임의로 결정 (서버 상태가 이긴다)
```
