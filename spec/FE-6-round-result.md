# FE-6 · round-result

**의존** FE-5 capture
**요구사항** RS-01 ~ RS-15, RX-01 ~ RX-10, PV-02, PV-04
**화면** 8 라운드 결과 · 9 라운드 미참여 안내
**결정** C-2 (캐러셀 + 레일), C-3 (제출 즉시 전환), C-4 (리액션), C-10 (감상 시간·스킵)

---

## 목표

**제출한 사람부터 즉시** 결과를 보여주고, 뒤이어 들어오는 카드가 실시간으로 끼어들며 순위가 재정렬되는 것을 보게 한다. 먼저 낸 사람은 자기 순위가 밀리는 것을 지켜보며 기다린다 — 그게 이 화면의 재미다.

FE에서 가장 복잡한 화면이다. 그리고 **미제출자에게 결과가 새면 안 되는** 화면이다.

---

## 화면 8 — 레이아웃

```
┌─────────────────────────────────┐
│ [3/5 라운드]      [실시간 집계 중]│
│ [😲 놀람]         내 점수 84 ·2위│
│ ┌─────────────────────────────┐ │
│ │ [1위 지수]            [92점]│ │
│ │                             │ │
│ │ ‹        셀카 크게        › │ │  ← 캐러셀
│ │                             │ │
│ │      [ ♥ ]    [ ⁇ ]         │ │
│ │        ● ○ ○ ○ ○            │ │
│ └─────────────────────────────┘ │
│ 실시간 순위          3 / 5 채점  │
│  ①    ②    ③    ·    ·         │
│ [🖼]  [🖼]  [🖼]  [⏳]  [⏳]     │  ← 레일 (재정렬)
│ 지수  태호   나    ·    ·        │
│                                 │
│ [ 다음 라운드 · 2/3 · 00:14 ]   │  ← 스킵
└─────────────────────────────────┘
```

| ID | 규칙 |
|---|---|
| RS-02 | **사진 1장을 크게 보여주는 캐러셀** + 하단에 참여자 전원을 나열하는 **가로 순위 레일.** 캐러셀에는 사진·닉네임·감정 점수·현재 순위, 레일에는 썸네일·순위·리액션 수. |

세로 카드 목록을 쓰지 않는 이유: 12명 방에서 스크롤이 길어지고 셀카가 작아진다. **사진을 크게 보는 것이 이 게임의 재미**이므로, 순위 변동은 레일이 담당한다 (C-2).

## 동작 순서 (PRD 6.4)

1. 제출을 마치는 즉시 이 화면으로 전환된다. 내 자리는 레일에 **"판별 중"** 상태로 먼저 놓인다.
2. 점수가 확정되면 내 썸네일이 제 위치로 이동한다.
3. 다른 사람이 제출할 때마다 레일에 추가되고 재정렬된다. 내 순위가 밀리는 과정이 그대로 보인다.
4. **캐러셀에서 보고 있던 사진은 레일이 재정렬되어도 바뀌지 않는다.**
5. 도착해 채점이 끝난 사진에는 즉시 ♥·⁇를 줄 수 있다. 최종 정렬을 기다리지 않는다.
6. 상단에 `3 / 5 채점 완료`가 표시된다.
7. 전원이 확정되면 최종 정렬 후 라운드 포인트가 표시된다.
8. 감상 시간이 끝나거나, 방장이 넘기거나, 결과를 보는 전원이 스킵하면 다음 라운드로 간다.

## 캐러셀 — 가장 틀리기 쉬운 부분

| ID | 규칙 |
|---|---|
| RS-03 | **레일이 재정렬되어도 캐러셀이 현재 보고 있는 사진은 바뀌지 않는다.** |

시안 `RoundResult.dc.html`에 이 코드가 그대로 있다 (C-2, [Design Delta](../../emoselfie-DOCS/development/Design%20Delta.md) §RoundResult):

```js
const cur = ranked[cursor]      // ❌ cursor가 점수순 배열의 인덱스
```

재정렬되면 보고 있던 사진이 **예고 없이 다른 사람으로 바뀐다.** 남의 셀카를 보고 있다가 갑자기 다른 사람 얼굴로 전환된다.

```ts
// ✅ cursor를 인덱스가 아니라 participantId로 관리
const [cursorId, setCursorId] = useState<string | null>(null);
const cur = submissions.find(s => s.participantId === cursorId);
```

- 캐러셀에 사진이 없는 참여자(미제출)는 포함하지 않는다 (RS-06).
- 보고 있던 사람이 어떤 이유로 목록에서 빠지면 인접 항목으로 이동한다.
- 첫 진입 시 기본 커서는 내 카드. **[가정]**

## 레일 재정렬

| ID | 규칙 |
|---|---|
| RS-03 | 새 점수가 확정될 때마다 레일을 **감정 점수 내림차순**으로 재정렬하고 썸네일 이동 애니메이션을 보여준다. **300~500ms**, 연속 삽입 시 **큐로 처리해 겹치지 않게** 한다. |
| RS-04 | 판별 전까지는 "판별 중" 상태로 레일에 자리를 잡고, 점수 확정 시 이동한다. 미제출자는 레일 끝에 대기 상태로 표시한다. |
| RS-05 | `N / N 채점 완료`를 표시해 왜 기다리는지 알 수 있게 한다. |
| RS-06 | 마감 시 미제출자를 0점으로 레일 맨 뒤에 추가한다. 사진이 없으므로 캐러셀 대상에서 제외한다. |

정렬 기준은 **감정 점수**다. 순위 포인트가 아니다.

Motion의 layout animation을 쓴다. 여러 카드가 짧은 시간에 들어올 수 있으므로 **애니메이션을 동시에 무제한 실행하지 않는다** (가이드 §12). 큐로 순차 처리해 화면이 요동치지 않게 한다.

```
transform: translateX(...)
transition: 500ms cubic-bezier(.22, 1.2, .36, 1)
```

`prefers-reduced-motion`을 존중해 애니메이션을 줄인다. **[가정]**

### 중간 순위는 표시용이다

`submission:scored`의 `currentRank`는 **표시용**이다. 라운드 포인트는 `round:finalized`에서만 온다 (SC-09). FE가 중간 순위로 포인트를 계산해 미리 보여주지 않는다.

## 리액션

**점수에 반영되지 않는 순수한 반응이다** (C-4).

| | ♥ 좋아요 | ⁇ 물음표 |
|---|---|---|
| 의미 | 공감·재미. "이 표정 최고" | "띠용?" — 주제에 맞는 사진인지 의구심 |
| 향하는 대상 | 사진 | **엔진의 판정.** 사람이 아니다 |

물음표는 "빗나감조차 재미"라는 핵심 가설에서 나온 장치다. **사람을 향한 조롱으로 읽히는 라벨을 쓰지 않는다** (PRD 5.9).

| ID | 규칙 | FE 구현 |
|---|---|---|
| RX-01 | 점수·순위에 영향 없음 | 점수 옆에 보너스를 표시하지 않는다 |
| RX-02 | 사진 하나당 1회. 여러 사진에 각각 가능 | 카드별 상태 관리 |
| RX-03 | ♥와 ⁇ 독립. 같은 사진에 둘 다 가능 | 상호 배타 UI를 만들지 않는다 |
| RX-04 | **토글로 취소** | 증가가 아니라 토글 |
| RX-05 | 자기 사진 불가 | 내 카드에서 버튼 비활성 + 이유 |
| RX-06 | **도착해 채점이 끝나는 즉시** 가능 | 최종 정렬을 기다리지 않는다 |
| RX-09 | 리액션 수 실시간 표시. **누가 눌렀는지는 표시하지 않는다** | actor를 렌더링하지 않는다 |
| RX-10 | 라운드 종료 시점에 확정, 이후 변경 무시 | 종료 후 버튼 비활성 |

시안 `RoundResult.dc.html`에 그대로 있다 (C-4). `⁇` 버튼은 `hmm()`으로 **이미 구현되어 있으니 유지**하고, 아래만 고친다:

```js
const canLike = final && !curIsMe;         // ❌ final 조건 제거
// ✅ !curIsMe && cardScored

like(id) { likes[id] = (likes[id]||0)+1 }  // ❌ 증가
// ✅ 토글
```

`LK-01` ~ `LK-08`은 전부 폐기됐다. **라운드당 1표도, 5포인트 보너스도 없다.**

낙관적 업데이트를 하되 서버의 `reaction:updated`가 최종이다. 서버 값이 다르면 서버를 따른다.

## 스킵과 감상 시간

| ID | 규칙 |
|---|---|
| RS-07 | 전원 결과가 확정되면 최종 정렬을 마치고 라운드 획득 포인트를 표시한다. |
| RS-08 | 최종 정렬 이후 감상 시간. **`min(60, 10 + 참여 인원 × 2)`초.** 방장은 즉시 넘길 수 있다. |
| RS-15 | **결과를 보는 참여자 전원이 스킵을 누르면 즉시 다음 라운드로.** 방장 전용이 아니고, **토글로 취소** 가능하며, 현황을 `제출 인원/참여 인원`과 같은 형태로 표시한다. **미제출자는 분모에서 제외한다.** |

| 인원 | 2 | 5 | 8 | 12 |
|---|---|---|---|---|
| 감상 시간 | 14초 | 20초 | 26초 | 34초 |

디자인의 `isHost ? "스킵" : "다음 라운드까지"(비활성)`를 **전원 활성**으로 바꾼다 (C-10).

```
[ 다음 라운드 · 2/3 · 00:14 ]
              ↑     ↑
       스킵 현황   남은 감상 시간
```

`3 / 5 넘길 준비` 현황은 RD-09의 제출 현황과 **같은 패턴을 재사용**한다.

분모(`total`)는 서버가 준다. FE가 참여자 수에서 계산하지 않는다 — 미제출자 제외 규칙이 FE에서 어긋나면 "전원 스킵했는데 안 넘어감"이 된다.

감상 시간 카운트다운도 서버가 준 절대 마감 시각 기준이다 (RD-08).

## 화면 9 — 라운드 미참여 안내

| ID | 규칙 |
|---|---|
| RS-11 | 제한시간 내 제출하지 못한 참여자는 **그 라운드 결과를 볼 수 없다.** 사진·점수·순위·리액션 어느 것도 노출하지 않고 대기 안내 화면으로 보낸다. |
| RS-12 | 차단은 **서버가 이벤트를 발행하지 않는 방식**이다. |
| RS-14 | 이번 라운드를 놓쳤다는 사실과 **다음 라운드까지 남은 시간만** 표시한다. 다른 참여자의 점수나 누적 순위를 노출하지 않는다. |

화면에 담는 것:

```
이번 라운드를 놓쳤어요
다음 라운드까지 00:12
```

담지 않는 것:

```
❌ 다른 참여자의 사진·점수·순위   ❌ 누적 순위   ❌ 리액션   ❌ 스킵 버튼
```

스킵 버튼이 없는 것이 RS-15의 분모 제외와 짝을 이룬다.

### FE의 역할

**보안을 Client UI에 의존하지 않는다** (가이드 §10). 다음은 금지다.

```
Backend에서 전체 결과 수신 → Frontend에서 display:none
```

FE는 **Backend가 허용한 정보만** 화면에 표시한다. 결과 데이터를 받지 못하는 것을 **정상 상태**로 처리한다 — 에러 화면을 띄우거나 재요청하지 않는다.

`round:missed`를 받으면 이 화면으로 간다. 이전 라운드의 결과 스토어를 비운다. 안 비우면 지난 라운드 데이터가 남아 보인다.

| ID | 규칙 |
|---|---|
| RS-13 | 페널티 대상은 **미제출자에 한한다.** 얼굴 미검출(SC-04)·판정 불가(SC-05)는 결과를 **정상적으로 본다.** |

`no_face`·`failed` 참여자를 이 화면으로 보내지 않는다. 그들은 화면 8을 정상적으로 본다.

## 프라이버시

| ID | 규칙 |
|---|---|
| PV-02 | 결과 화면 사진은 **서버 임시 캐시(Redis)에서 URL로 받아온다.** 라운드 종료 시 파기되며, 세션 종료 후 조회 경로가 존재해서는 안 된다. 이미지를 브라우저 저장소에 복제하지 않는다. |
| PV-04 | 타인 사진에 대해 **저장·캡처를 유도하는 기능(다운로드 버튼 등)을 제공하지 않는다.** |

라운드가 끝나면 이미지 참조를 정리하고 Blob URL을 해제한다.

---

## 문구

**문장은 놀리지 않는다** (PRD 6.5). 조롱·평가어를 쓰지 않으며, **낮은 점수도 경고색이 아니라 해당 감정의 색**으로 표시한다. 색은 서버가 `round:revealed`로 내려준 값을 쓴다.

`no_face`는 "얼굴을 찾지 못했어요" (SC-04), `failed`는 "판정 불가"로 표시한다. 두 문구를 섞지 않는다.

## 하지 않는 것

```
❌ cursor를 배열 인덱스로 관리 (RS-03 위반 — C-2의 명시된 버그)
❌ 세로 카드 목록 (C-2에서 캐러셀 + 레일로 변경)
❌ 전원 대기 후 결과 일괄 표시 (C-3에서 폐기)
❌ Play의 wait 대기 화면 (C-3에서 삭제)
❌ 리액션을 최종 정렬 이후에만 활성화 (RX-06)
```
