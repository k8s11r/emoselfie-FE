# FE-3 · camera

**의존** FE-1 shell
**요구사항** PM-01 ~ PM-16, PV-03, CP-01
**화면** 3 카메라 사전 안내 · 4 참여 불가 안내
**결정** C-7 (권한 미허용자는 대기실 입장 차단)

---

## 목표

권한 요청은 게임 성립 여부를 좌우한다. 핵심 원칙 한 줄:

> **라운드가 시작되기 전에, 사용자가 이유를 이해한 상태에서, 사용자의 탭으로 요청한다.**

이 모듈을 **두 번째로 만든다.** 카메라는 데스크톱에서 검증되지 않고, 실기기 이슈가 늦게 터지면 이후 화면 설계가 흔들린다.

---

## 요청 시점

| 단계 | 동작 |
|---|---|
| 랜딩 / 닉네임 입력 | **권한 요청하지 않음.** 브라우저 다이얼로그를 맥락 없이 띄우면 반사적으로 거부된다 |
| 닉네임 입력 직후 | "카메라 준비" 화면. 왜 필요한지 + 사진이 저장되지 않는다는 안내를 1~2줄로 |
| 사용자가 "카메라 켜기" 탭 | **이때 처음으로** 브라우저 권한 다이얼로그 호출 |
| 대기실 | 권한을 허용한 사용자만 입장 |
| 촬영 화면 | **권한 요청 없음.** 이미 허용된 권한으로 스트림만 재개 |

| ID | 규칙 |
|---|---|
| PM-01 | 브라우저 권한 다이얼로그는 **사용자의 명시적 탭에 의해서만** 호출한다. 페이지 로드 시 자동 호출 금지. |
| PM-02 | 요청 전 사전 안내 화면에서 사용 목적과 **"라운드가 끝나면 바로 삭제"** 를 함께 고지한다. |
| PV-03 | 첫 촬영 화면 진입 시에도 **"사진은 라운드가 끝나면 바로 삭제돼요"** 를 명시한다. 실제 보관 기간과 다른 표현을 쓰지 않는다. |

`getUserMedia()`를 `useEffect` 안에서 무조건 호출하지 않는다. 이 한 줄이 PM-01 위반의 가장 흔한 형태다.

## 권한 상태

| ID | 규칙 |
|---|---|
| PM-03 | 상태를 **`허용 / 거부 / 미요청 / 기기 없음`** 4가지로 구분해 관리한다. |
| PM-15 | Permissions API를 지원하지 않는 브라우저에서는 **실제 스트림 획득 시도 결과**로 판단한다 (P1). |

```ts
type CameraPermission = 'granted' | 'denied' | 'prompt' | 'no_device';
```

iOS Safari의 `navigator.permissions.query({name:'camera'})` 지원은 버전마다 다르다. 조회 실패를 정상 경로로 취급하고 시도 결과로 판단한다.

`getUserMedia` 실패는 에러 이름으로 구분한다. **[가정]**

```
NotAllowedError    → denied      → 화면 4 (설정 안내)
NotFoundError      → no_device   → 화면 4 (기기 없음 메시지)
NotReadableError   → 점유 중     → PM-09 (다른 앱 사용 중 + 재시도)
OverconstrainedError → 제약 완화 후 재시도
```

## 화면 3 — 카메라 사전 안내

내용:

- 이 게임에는 카메라가 필요하다
- 촬영된 사진은 감정 판별에 사용된다
- **사진은 라운드가 끝나면 바로 삭제돼요** ← PRD v1.1 확정 문구
- `카메라 켜기` 버튼

"판별 후 즉시 삭제"라고 쓰지 않는다. 결과 화면 캐러셀을 위해 사진은 감상 시간이 끝날 때까지(12명 방 기준 약 60초) 서버 임시 캐시에 있다. 문구와 실제를 맞추기로 결정했다 (PRD v1.1, PV-03).

버튼을 누른 순간이 **처음이자 유일한** 권한 요청 시점이다.

## 화면 4 — 참여 불가 안내

| ID | 규칙 |
|---|---|
| PM-06 | **카메라 권한은 참여의 필수 조건이다.** 사진첩·파일 업로드 등 대체 제출 수단을 일절 제공하지 않는다. |
| PM-07 | 권한이 없으면 **대기실 입장 자체를 차단한다.** 방 이름·참여 인원·라운드 진행·다른 참여자의 사진·점수 어느 것도 볼 수 있는 경로를 두지 않는다. |
| PM-05 | 거부 시 브라우저가 다이얼로그를 재노출하지 않으므로, 재요청 버튼 대신 **브라우저·OS별 설정 변경 방법 안내 시트**를 제공한다. |
| PM-08 | 이 화면에서 권한을 허용하면 **즉시 대기실로 입장**한다. 게임이 진행 중이면 다음 게임부터 참여 (RO-09). |
| PM-09 | 카메라가 없거나 다른 앱이 점유해 실패한 경우, **거부와 구분되는 메시지**와 재시도 버튼을 제공한다. |

문구 (PRD 5.5):

```
제목  카메라 없이는 참여할 수 없어요
본문  이 게임은 지금 찍은 셀카로만 진행돼요.
      사진은 라운드가 끝나면 바로 삭제됩니다.
      브라우저 설정에서 카메라를 허용하면 참여할 수 있어요.
액션  [설정 방법 보기]  [다시 시도]
```

### 설정 안내 시트 (PM-05)

iOS Safari와 Android Chrome **각각의 경로**를 그림 또는 단계 텍스트로 안내한다. 하나의 범용 문구로 뭉뚱그리지 않는다. 사용자가 이 시트를 보고 실제로 설정을 바꿔 돌아오는 비율이 PRD 2.2의 "권한 거부 후 재허용률 40%" 지표다.

시트를 띠운 상태에서 사용자가 앱을 전환해 설정을 바꾸고 돌아오면, `visibilitychange`에서 권한을 재확인해 자동으로 대기실로 보낸다 (PM-08 + PM-12).

### 이 화면에서 보이지 않아야 하는 것

```
❌ 방 이름 (애초에 없다)   ❌ 참여 인원
❌ 라운드 진행 상황        ❌ 다른 참여자의 사진·점수
❌ 참여자 목록
```

서버도 이 정보를 주지 않지만, FE가 이전에 받아둔 값을 남겨 표시하지 않도록 진입 시 관련 스토어를 비운다.

## 스트림 수명 관리

| ID | 규칙 |
|---|---|
| PM-04 | 권한 확인 후 **미디어 트랙을 즉시 정지**시켜 대기실에서 카메라가 켜진 채 유지되지 않게 한다. 촬영 화면 진입 시 재시작하며, 이때 권한 다이얼로그는 다시 뜨지 않는다. |

```ts
stream.getTracks().forEach(track => track.stop());
```

목적: 배터리·발열 감소, 그리고 **사용자의 카메라 사용 불안감 감소**. 대기실에서 카메라 표시등이 켜져 있으면 "사진이 저장되지 않는다"는 약속이 의심받는다.

```
권한 확인 → 트랙 정지 → 대기실 → 촬영 화면 진입 → 스트림 재생성
```

트랙 정지와 재생성을 `useCameraStream`이 단독으로 책임진다. FE-4와 FE-5가 각자 스트림을 만들면 대기실에 카메라가 켜진 채로 남는 경로가 생긴다.

## 앱 전환·화면 잠금 복귀

| ID | 규칙 |
|---|---|
| PM-13 | 앱 전환·화면 잠금으로 스트림이 중단된 뒤 복귀하면 **프리뷰를 자동 재개**한다. 실패 시 "카메라 다시 켜기" 버튼을 노출한다. |
| PM-12 | 새로고침·재접속 시 이전 권한 상태를 재확인하고, 이미 허용된 경우 **추가 요청 없이 준비 완료로 복원**한다. |

모바일에서 일상적으로 일어나는 일이다: 전화 수신, 앱 전환, 브라우저 background, 화면 잠금, 브라우저 복귀.

```ts
useVisibilityResume()   // visibilitychange + pagehide/pageshow
```

복귀 시 `videoTrack.readyState === 'ended'`이면 스트림을 다시 만든다. 자동 복구가 실패하면 버튼을 노출한다 — **무한 로딩으로 두지 않는다.**

| ID | 규칙 |
|---|---|
| PM-11 | 라운드 중 권한이 철회되거나 스트림이 영구 손실되면, 서버에 `permission:changed`를 통보한다. 서버가 미제출 처리 + 퇴장 + 화면 4 이동을 결정한다. 누적 포인트는 보존된다. |

FE는 통보만 하고 판정하지 않는다.

## HTTPS

| ID | 규칙 |
|---|---|
| PM-14 | HTTPS가 아니면 카메라 API가 동작하지 않는다. **전 구간 HTTPS 전제.** |

개발 환경에서도 실기기 테스트에는 HTTPS가 필요하다. `localhost`는 secure context 예외지만 LAN IP는 아니다. 로컬 인증서 또는 터널을 붙인다 (루트 SPEC §5).

## 테스트

### 자동

- 페이지 로드만으로 `getUserMedia`가 호출되지 않는다 (PM-01)
- 버튼 탭 시 정확히 1회 호출
- `NotAllowedError` → `denied` → 화면 4
- `NotFoundError` → `no_device` → 기기 없음 메시지
- `NotReadableError` → 점유 중 메시지 + 재시도 (거부와 **다른** 문구, PM-09)
- 권한 확인 후 모든 트랙이 `stop()` 된다 (PM-04)
- Permissions API 미지원 환경에서 스트림 시도 결과로 판단 (PM-15)
- 화면 4에 방 정보·인원·참여자가 렌더링되지 않는다 (PM-07)
- 사전 안내 화면에 "라운드가 끝나면 바로 삭제" 문구가 있다 (PM-02)
- 앱 전체에서 "판별 후 즉시 삭제" 문구가 검색되지 않는다 (PRD v1.1)

### 실기기 (필수 — Desktop Chrome 통과로 대체 불가)

```
[iOS Safari 최신 2개 / Android Chrome 최신 2개]
□ 최초 권한 다이얼로그가 버튼 탭으로만 뜬다
□ 거부 후 설정 안내 시트가 해당 OS 경로를 보여준다
□ 설정에서 허용 → 앱 복귀 → 자동으로 대기실 입장 (PM-08)
□ 대기실에서 카메라 표시등이 꺼져 있다 (PM-04)
□ 촬영 화면 진입 시 다이얼로그가 다시 뜨지 않는다
□ 전화 수신 → 복귀 → 프리뷰 자동 재개 (PM-13)
□ 앱 전환 → 복귀 → 프리뷰 자동 재개
□ 화면 잠금 → 복귀 → 프리뷰 자동 재개
□ 자동 재개 실패 → "카메라 다시 켜기" 버튼
□ 다른 앱이 카메라 점유 중 → 구분되는 메시지 (PM-09)
□ 새로고침 → 추가 요청 없이 준비 완료 복원 (PM-12)
```

## 하지 않는 것

```
❌ 페이지 로드 시 getUserMedia 자동 호출 (PM-01)
❌ 랜딩·닉네임 단계에서 권한 요청
❌ 거부 후 getUserMedia 재호출로 다이얼로그 재시도 (PM-05)
❌ 대기실에서 스트림 유지 (PM-04)
❌ 화면 4에 방 정보·인원 노출 (PM-07)
❌ 사진첩·파일 선택 대체 경로 (PM-06)
❌ 거부와 기기 없음·점유 중을 같은 메시지로 처리 (PM-09)
❌ 촬영 화면에서 권한 재요청 (CP-01)
❌ 복구 실패 시 무한 로딩
❌ FE-4·FE-5가 각자 스트림 생성
❌ 권한 철회 시 FE가 미제출·퇴장을 판정 (PM-11은 서버 몫)
```
