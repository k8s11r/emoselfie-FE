# FE-4 · lobby

**의존** FE-3 camera
**요구사항** RO-06 ~ RO-09, RO-13, RO-17, RD-01, RD-04, PM-10
**화면** 5 대기실
**결정** C-7 (연결 상태), C-8 (CODE 삭제), C-9 (방 이름 삭제)

---

## 목표

사람이 모이는 것을 보여주고, 방장이 설정을 바꾸고 시작하게 한다.

---

## 구성

```
초대 링크 복사
참여 인원 현황
인원별 연결 상태
게임 설정 변경 (방장)
시작하기 (방장)
방 닫기 (방장)
```

**두지 않는 것:**

```
❌ CODE 배지          링크 전용 (C-8)
❌ 방 이름 헤더        방에는 이름이 없다 (C-9)
❌ 준비 상태 프로그레스 바   항상 100%가 된다 (C-7)
❌ 로스터 denied 항목   권한 미허용자는 여기 없다 (PM-07)
```

방 이름이 있던 헤더 자리는 **설정 요약**으로 채운다 (C-9).

```
5라운드 · 20초 · 최대 12명
```

---

## 로스터

| ID | 규칙 |
|---|---|
| RO-07 | 참여자 목록과 각자의 **연결 상태**를 실시간 표시한다. 대기실에는 카메라 권한을 허용한 사용자만 존재하므로 **권한 상태는 표시 대상이 아니다.** |

C-7의 파생 결정이다. 전원이 권한을 허용한 상태이므로 "준비 상태"를 표시할 대상이 없다. 디자인의 배지 4종을 2종으로 줄인다.

```
배지: 준비 완료 / 입장 중
인원: 5 / 12명       ← 준비율이 아니라 정원 대비 인원
```

`participant:updated`로 연결 상태 변경을 받는다. 소켓이 끊긴 참여자는 즉시 목록에서 빼지 않는다 — 재접속이 정상 동작이므로 `offline` 표시로 남긴다.

색상 태그로 참여자를 구분한다. 닉네임 중복이 허용되므로 색이 실질적 구분자다.

## 정원

| ID | 규칙 |
|---|---|
| RO-06 | 최소 2명, 최대 **12명**. 가득 찬 상태에서 접속하면 "방이 가득 찼어요"로 입장 거부 (화면 11). |

12명이 한 화면에 들어가야 한다. 세로 모드 기준으로 스크롤 없이 보이는 레이아웃을 만든다.

---

## 시작

| ID | 규칙 |
|---|---|
| RO-08 | 게임 시작은 **방장만.** 대기실 인원 **2명 이상**일 때 활성화. |
| PM-10 | 대기실에는 권한 허용자만 있으므로 조건은 인원 수뿐이다. |

비활성 버튼에는 **반드시 이유 문구를 동반한다.**

```
[ 게임 시작 ]  ← 비활성
2명부터 시작할 수 있어요
```

참여자에게는 시작 버튼 대신 "방장이 시작하기를 기다리는 중" 안내를 보여준다. 무한 로딩처럼 보이지 않게 인원 현황을 함께 표시한다 (PRD 6.5).

## 설정 변경

| ID | 규칙 |
|---|---|
| RO-17 | 방 만들기에서 지정한 라운드 수·제한시간을 **대기실에서 게임 시작 전까지 변경할 수 있다.** |

```
PATCH /api/rooms/{slug}/settings
```

랜딩과 **같은 칩 UI 패턴**을 재사용한다 (C-5).

```
라운드 수    [ 3 ]  [ 5 ]  [ 7 ]
제한시간     [ 15초 ] [ 20초 ] [ 30초 ]
```

방장만 조작 가능. 참여자에게는 읽기 전용으로 현재 설정을 보여준다. 설정이 바뀌면 전원 화면이 갱신된다.

`status`가 `playing`이 되면 변경 UI를 감춘다.

## 초대 링크

```
emoselfie.app/r/Xk9mQ2vB7nLp
```

복사 버튼 + 복사 완료 피드백. Web Share API가 있으면 공유 시트도 제공한다. **[가정]**

서버가 준 URL을 그대로 쓴다. FE가 조립하지 않는다.

## 방 닫기

| ID | 규칙 |
|---|---|
| RO-13 | 방장은 방을 명시적으로 닫을 수 있다. 닫으면 참여자 전원에게 알리고 소유 슬롯을 즉시 반환한다. |

방장이 새 방을 만들려면 기존 방을 닫아야 한다 (RO-03의 짝). 이 버튼이 없으면 사용자가 영영 새 방을 못 만든다.

파괴적 동작이므로 확인 단계를 둔다. **[가정]**

`room:closed` 수신 시 전원이 안내와 함께 랜딩으로 이동한다.

---

## 게임 중 입장

| ID | 규칙 |
|---|---|
| RO-09 | 게임 진행 중 입장한 사용자는 대기실에 머물며 "게임이 진행 중이에요. 다음 게임부터 참여할 수 있어요"를 표시한다. **진행 중인 라운드의 주제·사진·점수는 노출하지 않는다.** |

서버가 라운드 이벤트를 보내지 않는다. FE는 받지 않은 정보를 추론해 채우지 않는다.

이 사용자에게 남은 라운드 수나 진행률도 보여주지 않는다 — 게임 내용에 해당한다.

---

## 방장 이탈

`host:changed`를 받으면 로스터와 버튼 권한을 갱신한다.

| 상황 | 표시 |
|---|---|
| 방장 이탈 60초 유예 중 (RO-10) | 방장 자리 비어 있음. 게임은 계속 |
| 임시 위임 (RO-11, `isTemporary: true`) | 새 방장 표시. "임시" 뉘앙스를 문구로 |
| 원래 방장 복귀 | 권한 반환. 조용히 갱신 |

FE는 60초를 세지 않는다. 서버가 `host:changed`를 보내면 따른다.

## 테스트

- CODE 배지가 렌더링되지 않는다 (C-8)
- 방 이름이 렌더링되지 않고 설정 요약이 그 자리에 있다 (C-9)
- 준비 상태 프로그레스 바가 없다 (C-7)
- 로스터 배지가 준비 완료 / 입장 중 2종뿐이다
- 로스터에 `denied` 항목이 없다 (PM-07)
- 인원 표시가 `5 / 12명` 형태다
- 1명일 때 시작 버튼 비활성 + 이유 문구
- 2명이 되면 활성화 (RO-08, PM-10)
- 참여자에게 시작 버튼이 없다
- 참여자에게 설정 변경 UI가 없고 읽기 전용 표시
- 설정 변경 → 전원 화면 갱신
- `playing` 전환 후 설정 UI 사라짐
- 방 닫기 → 확인 단계 → 전원 `room:closed` → 랜딩
- 게임 중 입장 → 안내만, 라운드 주제·점수 미표시 (RO-09)
- `host:changed` → 버튼 권한 갱신
- 소켓 끊긴 참여자가 목록에서 사라지지 않고 `offline` 표시
- 12명 로스터가 세로 모드에서 스크롤 없이 보인다

---

## 하지 않는 것

```
❌ CODE 배지 · 방 이름 · 준비 상태 프로그레스 바
❌ 로스터에 권한 상태·denied 항목 표시 (C-7, PM-07)
❌ 비활성 버튼에 이유 문구 없이 두기
❌ FE가 방장 60초 유예를 카운트
❌ 게임 중 입장자에게 라운드 정보 노출 (RO-09)
❌ 소켓 disconnect 즉시 로스터에서 제거
❌ FE에서 초대 URL 조립
❌ 확인 없이 방 닫기
```
