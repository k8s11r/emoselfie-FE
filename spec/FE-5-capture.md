# FE-5 · capture

**의존** FE-3 camera, FE-4 lobby
**요구사항** CP-01 ~ CP-06, RD-03, RD-08 ~ RD-10, EM-02, PV-03, PV-05
**화면** 6 라운드 시작 · 7 촬영
**결정** C-5 (제한시간 20초), C-6 (건너뛰기·자동 제출 삭제)

## 목표

20초 안에 표정을 짓고 셔터를 누르게 한다. 프리뷰가 화면의 대부분을 차지하고, 텍스트는 최소로.

## 화면 6 — 라운드 시작

감정 카드 공개 + **3초 카운트다운**. 전원 동시 전환 (RD-02, RD-03).

서버의 `round:revealed`가 내려주는 것 (EM-02):

```
{ index, totalRounds,
  emotion: { label, displayName, emoji, hint, color },
  revealAt, deadlineAt }
```

**표시 이름·이모지·설명·색을 FE에 하드코딩하지 않는다.** 서버가 준다 (C-1). 문구를 고칠 때 FE 배포가 필요 없어야 한다.

```
😢
슬픔
"눈물이 핑 돌 것처럼"
```

카운트다운은 `revealAt`부터 `deadlineAt`까지의 서버 시각 기준이다. 3초를 FE가 세지 않는다.

## 화면 7 — 촬영

```
┌─────────────────────────────────┐
│ [3/5]                    [00:12]│  ← 좌: 제출 현황 / 우: 타이머
│                                 │
│           슬픔 😢               │  ← 상단 고정: 이번 라운드 주제
│                                 │
│  ┌───────────────────────────┐  │
│  │                           │  │
│  │      카메라 프리뷰        │  │  ← 전면 카메라 3:4
│  │                           │  │
│  └───────────────────────────┘  │
│                                 │
│            ( ● )                │  ← 촬영 버튼
│                                 │
└─────────────────────────────────┘

촬영 후 → 하단이 [다시 찍기] [제출하기] 로 전환
```

| 위치 | 내용 | 근거 |
|---|---|---|
| 상단 고정 | 이번 라운드 주제 | 화면이 바뀌는 순간 무엇을 표현할지 잊는 것을 막는다 |
| 좌상단 | `제출 인원/참여 인원` | RD-09 |
| 우상단 | 남은 시간 | RD-03 |
| 하단 | 촬영 버튼 → 다시 찍기 / 제출하기 | CP-02 |

**두지 않는 것:**

```
❌ 건너뛰기 버튼                    RD-10, C-6
❌ "시간이 끝나면 자동 제출돼요" 문구  RD-10, C-6
❌ 파일 선택 입력                   CP-03, PM-06
```

### 타이머

| ID | 규칙 |
|---|---|
| RD-03 | 남은 시간은 촬영 화면 **우측 상단에 항상** 표시한다. |
| RD-08 | 서버가 준 `deadlineAt` 기준. 화면 로딩 시점부터 자체 카운트하지 않는다. |

잔여 10초부터 색을 바꿔 강조하되 **진동·소리로 압박하지 않는다** (PRD 6.2).

타이머가 0에 닿아도 FE는 아무것도 판정하지 않는다. 서버 이벤트를 기다린다 (FE-1 §서버 시각).

### 제출 현황

| ID | 규칙 |
|---|---|
| RD-09 | `제출 인원/참여 인원`을 실시간 표시. **대기 중인 사용자는 분모에 포함하지 않는다.** |
| RS-09 | 아직 제출하지 않은 참여자에게 **다른 사람의 점수를 노출하지 않는다.** 제출 인원 수만 표시한다. |

`submission:status`에는 점수가 없다. 있어도 표시하지 않는다.

### 프리뷰

| ID | 규칙 |
|---|---|
| CP-01 | 전면 카메라를 인앱 프리뷰로 사용한다. 촬영 버튼 1탭으로 캡처. **이 화면에서 권한을 새로 요청하지 않는다.** |
| CP-06 | 진입 후 **1.5초** 내 프리뷰가 안 뜨면 로딩 표시, **3초** 내 실패하면 재시도 버튼. 끝내 실패해 미제출된 경우 SC-05(판정 불가)에 준해 처리한다. |
| PV-03 | 첫 촬영 화면 진입 시 **"사진은 라운드가 끝나면 바로 삭제돼요"** 를 명시한다 (PRD v1.1). |

스트림은 FE-3의 `useCameraStream`이 재생성한다. 권한 다이얼로그는 다시 뜨지 않는다 (PM-04).

프리뷰 실패 시 갤러리 폴백을 제안하지 않는다 (구 CP-07, v0.3에서 폐기).

## 캡처와 압축

| ID | 규칙 |
|---|---|
| CP-04 | 업로드 전 클라이언트에서 리사이즈·압축한다. **장변 최대 720px, JPEG 품질 0.8.** |
| — | 무거운 이미지 라이브러리를 추가하지 않는다. 브라우저 API 우선. |

```
Camera → video → Canvas capture → Resize → JPEG 0.8 → Blob → HTTP Upload
```

```ts
canvas.toBlob(callback, "image/jpeg", 0.8);
```

**비율을 유지한다.**

```
3024 × 4032  →  540 × 720
```

장변이 720 이하인 원본은 확대하지 않는다.

전면 카메라 프리뷰를 좌우 반전해 보여주는 경우, **업로드 이미지에는 반전을 적용하지 않는다.** 판별 모델에 거울상을 보내면 결과가 달라질 수 있다. **[가정]** — 원본 문서에 규정이 없다.

## 업로드

```
POST /api/rooms/{slug}/rounds/{roundId}/submissions
Content-Type: multipart/form-data
Headers: X-Capture-Token
```

이미지는 **HTTP로 보낸다. Socket.IO로 binary를 보내지 않는다** (가이드 §6).

| ID | 규칙 |
|---|---|
| CP-05 | 업로드 실패 시 **자동 1회 재시도**하고, 그래도 실패하면 재시도 버튼을 노출한다. |
| — | **업로드가 시작됐다는 이유로 제출을 성공 처리하지 않는다.** Backend 응답 또는 서버 이벤트를 기다린다. |

```
캡처 → 제출 탭 → 업로드 중 → 202 수신 → 결과 화면으로 전환
                            → 실패 → 자동 1회 재시도
                                   → 재실패 → 재시도 버튼
                            → 410 DEADLINE_PASSED → 미참여 화면 (재시도 유도 없음)
```

업로드 중 UI는 진행 상황을 보여준다. 무한 스피너로 두지 않는다.

서버가 `202`를 주면 제출이 접수된 것이고, **채점 결과는 소켓으로 온다.** 202를 받는 즉시 결과 화면(FE-6)으로 전환한다 — 내 카드는 "판별 중"으로 놓인다 (RS-01, RS-04).

## 이미지 수명

| ID | 규칙 |
|---|---|
| — | 촬영 이미지를 `localStorage` `sessionStorage` `IndexedDB` `Cache Storage`에 저장하지 않는다. |
| — | UI용 Blob URL은 사용이 끝나면 **반드시 `URL.revokeObjectURL()`** 로 해제한다. |
| PV-05 | 로그·에러 리포팅에 이미지나 base64를 남기지 않는다. |

페이지 lifecycle보다 오래 이미지가 남지 않게 한다. 다시 찍기를 누르면 이전 Blob URL을 즉시 해제한다.

에러 리포팅 도구를 붙일 경우, Blob·base64가 페이로드에 실리지 않도록 필터를 건다. **[가정]**

## 테스트

### 자동

- 3024×4032 → 540×720 (비율 유지)
- 640×480 → 확대하지 않음
- `toBlob`이 `image/jpeg`, 0.8로 호출됨
- 업로드 Blob이 원본보다 작다
- 좌우 반전 프리뷰의 업로드 이미지가 반전되지 않았다
- 촬영 화면에 파일 선택 input이 없다 (CP-03)
- 건너뛰기 버튼이 없다 (RD-10)
- 시안의 `seconds ?? 30` 기본값이 20으로 반영됐다 (C-5, Design Delta §Play)
- "자동 제출" 문구가 없다 (C-6)
- 타이머가 `deadlineAt` 기준이다
- 잔여 10초부터 색 변경, 진동·소리 없음
- `submission:status`에 점수가 있어도 표시하지 않는다 (RS-09)
- 업로드 시작만으로 결과 화면 전환하지 않는다
- 업로드 실패 → 자동 1회 재시도 → 재실패 → 버튼 (CP-05)
- `410` 수신 → 미참여 화면, 재시도 버튼 없음 (CP-10)
- 다시 찍기 시 이전 Blob URL 해제
- 언마운트 시 모든 Blob URL 해제
- 이미지가 어떤 브라우저 저장소에도 없다
- 마감 후 다시 찍기·제출 버튼 비활성 (CP-02)

### 실기기

```
□ 전면 카메라 프리뷰가 3:4로 뜬다
□ 진입 1.5초 내 프리뷰, 실패 시 로딩 → 3초 후 재시도 버튼 (CP-06)
□ 촬영 버튼 1탭으로 캡처
□ Blob 업로드 성공 (iOS Safari / Android Chrome)
□ 촬영 중 앱 전환 → 복귀 시 프리뷰 재개, 타이머는 계속 흐름
□ 4G에서 업로드가 마감을 넘겨도 서버가 인정 (CP-08 — 2기기 확인)
```

## 하지 않는 것

```
❌ 원본 해상도 전송 (CP-04)
❌ Socket.IO로 이미지 binary 전송
❌ 파일 선택 · 사진첩 경로 (CP-03, PM-06)
❌ 건너뛰기 버튼 · 자동 제출 (RD-10, C-6)
❌ 프리뷰 실패 시 갤러리 폴백 제안 (v0.3 폐기)
❌ 업로드 시작 = 제출 성공 처리
❌ 클라이언트 타이머로 마감 판정
❌ 이미지를 브라우저 저장소에 보관
❌ Blob URL 미해제
❌ 감정 표시 이름·색·설명 하드코딩 (EM-02)
❌ 타이머 진동·소리
❌ 업로드 중 무한 스피너
❌ 마감 후 재시도 유도 (CP-10)
```
